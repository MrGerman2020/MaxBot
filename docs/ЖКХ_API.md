# Почему обращения не отправляются через РИАС ЖКХ

Коротко: **подать обращение гражданина через API РИАС ЖКХ нельзя.** Это не
недоделка в коде, а ограничение архитектуры ГИС ЖКХ.

## Что представляет собой API РИАС ЖКХ

`https://api.rias-gkh.ru/v2.0/` — интеграционный API для **управляющих
организаций и РСО** ([rias-gkh.ru/api](https://rias-gkh.ru/api)).

Токен выдаётся в личном кабинете после регистрации **организации**.

Эндпоинт `POST /appeals` в схеме `AppealImportForm` содержит поля:

| Поле | Назначение |
|---|---|
| `organization_id` | организация, которая импортирует |
| `executor_id` | исполнитель по обращению внутри организации |
| `applicant_org_guid` | заявитель-организация |
| `applicant_type` | тип заявителя — **организация**, не физлицо |

То есть `/appeals` — это импорт обращений, которые УК **уже получила** по своим
каналам (телефон, почта, личный приём) и загружает их в ГИС ЖКХ для учёта и
контроля сроков ответа.

## Подтверждение от оператора ГИС ЖКХ

Рабочая встреча 21.01.2026, Экспертный совет по ЖКХ при Комитете Госдумы,
АО «Оператор ГИС ЖКХ» и Ассоциация «Новое качество»:

> «Текущая архитектура позволяет загружать ответы на обращения, созданные
> в ГИС ЖКХ, через API. Однако если обращение возникло вне системы
> (например, в CRM или мессенджере), его невозможно корректно связать с
> личным кабинетом жителя без идентификации через Госуслуги.
> **Это ограничение признано принципиальным.**»

Там же по мессенджеру МАКС:

> «регистрация обращений не будет происходить напрямую в чатах: пользователь
> может редактировать сообщение после отправки, что нарушает правовую
> определённость. Поэтому подача обращений будет осуществляться только через
> мини-приложение "Госуслуги Дом", интегрированное с ГИС ЖКХ и требующее
> авторизации через Госуслуги.»

Источник: [sovetgkh.ru](https://sovetgkh.ru/news/sostoyalas-rabochaya-vstrecha-po-voprosam-razvitiya-gis-zhkh-api-obrascheniy-grazhdan-vzaimodeystviya-s-messendzherom-maks/)

С 1 апреля 2026 официальный чат-бот «Госуслуги Дом» доступен в домовых чатах
мессенджера MAX: <https://max.ru/gosuslugi_dom_bot>.

## Какие каналы реализованы в боте

### 1. Email в управляющую организацию — основной автоматический

Письменное обращение по ст. 11 ЖК РФ / 59-ФЗ. Работает сразу после заполнения
SMTP-настроек. Бот собирает адрес, категорию, ФИО, текст, email УК и email для
ответа, формирует письмо по требованиям ст. 7 59-ФЗ и отправляет.

Настройка в `.env`:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USERNAME=ваш@ящик.ru
SMTP_PASSWORD=пароль_приложения
SMTP_USE_TLS=1
```

Для Яндекса и Mail.ru нужен **пароль приложения**, а не пароль аккаунта.

### 2. «Госуслуги Дом» — официальная альтернатива

Кнопки в карточке обращения ведут на мини-приложение и личный кабинет
ГИС ЖКХ. Это единственный канал, который даёт обращению полную юридическую
силу с идентификацией через Госуслуги.

## Юридические нюансы

Обращение в электронной форме должно содержать (ст. 7 59-ФЗ):

- ФИО заявителя;
- адрес места жительства;
- адрес электронной почты для ответа;
- тему обращения;
- суть;
- **подпись**;
- дату.

Все эти поля бот подставляет в письмо автоматически.

Важное различие:

- В **государственные органы** по 574-ФЗ (с 30.03.2025) обращение по email
  без идентификации **не рассматривается вовсе**.
- В **УК** обращение по email принимается и обрабатывается, но УК не обязана
  соблюдать 30-дневный срок так же строго, как госорган. Практика зависит от
  конкретной УК.

Для гарантированной силы — ЭП или подача через «Госуслуги Дом».

## Что осталось в rias_api.py

Клиент сохранён для **чтения** реестров: договоры, лицевые счета, объекты
жилого фонда, приборы учёта, показания, платёжные документы. Метод
`create_appeal` удалён, чтобы его нельзя было вызвать по ошибке.
